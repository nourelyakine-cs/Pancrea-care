# Running PancreaCare on a local PostgreSQL

How to stand up a **fully local PostgreSQL** instance, load the PancreaCare
schema into it, and point the application at it.

This document changes **no application code**. The only file you need to edit
afterwards is `backend/.env`, which is git-ignored configuration — and you can
even skip that if you keep your Supabase database and just want a local copy to
experiment with.

## 1. What is actually needed

### The schema has no Supabase dependency

This is the single most important fact, and it was verified by grepping the
schema for every Supabase-specific construct:

| Construct searched | Occurrences |
|---|---|
| `auth.*` (Supabase Auth schema) | 0 |
| `storage.*` (Supabase Storage) | 0 |
| `CREATE EXTENSION` | 0 |
| `ENABLE ROW LEVEL SECURITY` | 0 |
| `CREATE POLICY` | 0 |
| `pg_graphql` / `realtime` / `pgbouncer` | 0 |

The schema is **plain PostgreSQL**. There is nothing to emulate and nothing to
strip out.

**No extension is required.** Every primary key is declared as:

```sql
id_medecin INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
```

so there is no dependency on `pgcrypto`, `uuid-ossp`, or `gen_random_uuid()`.
Standard `INT` identity columns need only **PostgreSQL >= 10**.

### Verified properties of the SQL files

| File | Encoding | Notes |
|---|---|---|
| `pancra_db_schema_supabase.sql` | UTF-8, no BOM | 32 202 bytes |
| `2026_08_29_medecin_hopital.sql` | UTF-8, no BOM | |
| `2026_09_02_decision_medecin.sql` | UTF-8, no BOM | |
| `2026_09_06_parcours_therapeutique_clinique.sql` | UTF-8, no BOM | |
| `2026_09_07_parcours_comorbidites.sql` | UTF-8, no BOM | |
| `2026_10_05_auth_compte_admin.sql` | UTF-8, no BOM | creates `compte`, `demande_reinitialisation` |
| `2026_10_05_auth_compte_admin_identite.sql` | UTF-8, no BOM | repair migration, safe on a fresh DB |
| `2026_10_05_dossier_patient_index_referent.sql` | UTF-8, no BOM | |
| `2026_10_05_super_admin_profil_medecin.sql` | UTF-8, no BOM | |

> If you see garbled characters such as `SCH�MA` when viewing these files, that
> is a **viewer encoding problem, not file corruption**. The bytes are valid
> UTF-8. `psql` reads them correctly as long as `PGCLIENTENCODING=UTF8` is set,
> which Method A does for you.

### The migrations are safe to replay

Every column addition uses `ADD COLUMN IF NOT EXISTS`, and table creation uses
`CREATE TABLE IF NOT EXISTS`. This matters for two reasons:

- `2026_10_05_auth_compte_admin_identite.sql` is a **repair** migration. It was
  written because an earlier version of
  `2026_10_05_auth_compte_admin.sql` had already been executed without the
  identity columns. On a brand-new database the columns already exist, so this
  file becomes a harmless no-op.
- Running the whole sequence twice changes nothing.

### Correct execution order

Alphabetical sorting happens to be the correct dependency order:

```
1. pancra_db_schema_supabase.sql        (base schema)
2. 2026_08_29_medecin_hopital.sql
3. 2026_09_02_decision_medecin.sql
4. 2026_09_06_parcours_therapeutique_clinique.sql
5. 2026_09_07_parcours_comorbidites.sql
6. 2026_10_05_auth_compte_admin.sql          -> creates `compte`
7. 2026_10_05_auth_compte_admin_identite.sql -> ADD COLUMN IF NOT EXISTS (no-op)
8. 2026_10_05_dossier_patient_index_referent.sql
9. 2026_10_05_super_admin_profil_medecin.sql
```

### Driver

`backend/requirements.txt` pins `psycopg[binary]==3.3.4` with SQLAlchemy
2.0.52. `backend/app/database.py` rewrites the URL scheme:

```python
database_url = settings.DATABASE_URL.replace(
    "postgresql://", "postgresql+psycopg://", 1
)
```

So a plain `postgresql://user:pass@host:5432/db` URL works — you do **not** need
to write `postgresql+psycopg://` yourself.

## 2. Method A — provisioning script (recommended)

Save the following as `pancreacare_local_postgres.ps1` and run it.

> **Encoding note.** If you save this as a `.ps1` file, use **UTF-8 with BOM**.
> PowerShell 5.1 assumes the system ANSI codepage for BOM-less files, and
> multi-byte characters such as `—` (U+2014) get misread. `E2 80 94` then
> decodes as `â€”`, where the byte `0x94` *is* a double quote — which silently
> terminates the surrounding PowerShell string and produces a parse error such
> as *"The terminator " is missing in the string."*

```powershell
<#
.SYNOPSIS
    Provisionne une base PostgreSQL locale pour PancreaCare et y charge le schema.
    Ne modifie AUCUN fichier du projet.
#>

[CmdletBinding()]
param(
    [string]$DbName        = "pancreacare",
    [string]$DbUser        = "pancreacare",
    [string]$DbPassword    = $null,
    [int]    $Port         = 5432,
    [string]$AdminPassword = $null,
    [switch]$AutoInstall
)

$ErrorActionPreference = "Stop"
$ProgressPreference    = "SilentlyContinue"

$Backend = "C:\Users\INFO\Desktop\CHU stage\Pancrea-care\backend"
$Schema  = Join-Path $Backend "database\pancra_db_schema_supabase.sql"
$MigDir  = Join-Path $Backend "database\migrations"

$script:Utf8NoBom = New-Object System.Text.UTF8Encoding($false)

function Say   { param($m) Write-Host $m }
function Ok    { param($m) Write-Host "  [OK]      $m" -ForegroundColor Green }
function Err   { param($m) Write-Host "  [ERREUR]  $m" -ForegroundColor Red }
function Warn  { param($m) Write-Host "  [ATTENTION] $m" -ForegroundColor Yellow }
function Etape { param($m) Write-Host "`n=== $m ===" -ForegroundColor Cyan }

function Invoke-Sql {
    param(
        [Parameter(Mandatory)][string]$Sql,
        [string]$Database = "postgres",
        [switch]$Silence
    )
    # Le SQL passe par un fichier temporaire UTF-8 sans BOM : transmettre du SQL
    # contenant des guillemets en argument natif est une source de corruption
    # silencieuse sous PowerShell.
    $tmp = [System.IO.Path]::GetTempFileName()
    [System.IO.File]::WriteAllText(
        $tmp, "\set ON_ERROR_STOP on`n" + $Sql, $script:Utf8NoBom
    )
    $sortie = & $psql -U postgres -h localhost -p $Port -d $Database -q -f $tmp 2>&1
    $code   = $LASTEXITCODE
    Remove-Item -LiteralPath $tmp -Force -ErrorAction SilentlyContinue

    if (-not $Silence) {
        foreach ($ligne in $sortie) {
            if ("$ligne" -match "ERROR|FATAL") { Err $ligne }
        }
    }
    return $code
}

function Find-Psql {
    $dansChemin = Get-Command psql -ErrorAction SilentlyContinue
    if ($dansChemin) { return $dansChemin.Source }

    foreach ($base in @("C:\Program Files\PostgreSQL", "C:\Program Files (x86)\PostgreSQL")) {
        if (-not (Test-Path $base)) { continue }
        foreach ($v in (Get-ChildItem $base -Directory | Sort-Object Name -Descending)) {
            $candidat = Join-Path $v.FullName "bin\psql.exe"
            if (Test-Path $candidat) { return $candidat }
        }
    }
    return $null
}

# --- 1. Localiser psql -------------------------------------------------------
Etape "1/6  Verification de PostgreSQL"
$psql = Find-Psql

if (-not $psql -and $AutoInstall) {
    Say "PostgreSQL absent, installation via winget..."
    winget install --id PostgreSQL.PostgreSQL --silent `
        --accept-package-agreements --accept-source-agreements
    if ($LASTEXITCODE -ne 0) { Err "winget a echoue"; exit 1 }
    $env:Path = [System.Environment]::GetEnvironmentVariable("Path", "Machine") + ";" +
                [System.Environment]::GetEnvironmentVariable("Path", "User")
    $psql = Find-Psql
}

if (-not $psql) {
    Err "PostgreSQL est introuvable (psql.exe)."
    Say "  winget install --id PostgreSQL.PostgreSQL"
    exit 2
}
Ok "psql : $psql"
& $psql --version

# --- 2. Serveur --------------------------------------------------------------
Etape "2/6  Serveur"
$service = Get-Service -Name "postgresql*" -ErrorAction SilentlyContinue |
           Sort-Object Name -Descending | Select-Object -First 1

if ($service -and $service.Status -ne "Running") {
    try { Start-Service $service.Name -ErrorAction Stop; Ok "service demarre" }
    catch { Warn "demarrage impossible : $($_.Exception.Message)" }
}

if (-not $AdminPassword) {
    Say ""
    Say "Mot de passe du role administrateur 'postgres' (Entree si aucun) :"
    $AdminPassword = Read-Host
}
$env:PGPASSWORD       = $AdminPassword
$env:PGCLIENTENCODING = "UTF8"

if ((Invoke-Sql "SELECT 1" -Silence) -ne 0) {
    Err "Connexion refusee sur localhost:$Port avec le role 'postgres'."
    exit 3
}
Ok "connexion etablie sur localhost:$Port"

# --- 3. Role applicatif ------------------------------------------------------
Etape "3/6  Role applicatif '$DbUser'"
$genere = $false
if (-not $DbPassword) {
    $octets = New-Object byte[] 18
    [System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($octets)
    $DbPassword = ([System.BitConverter]::ToString($octets) -replace '-', '').ToLower()
    $genere = $true
} elseif ($DbPassword -match '[@:/ ?#\[\]%]') {
    Err "Mot de passe incompatible avec une URL de connexion."
    exit 4
}

if ((Invoke-Sql "SELECT 1 FROM pg_roles WHERE rolname = '$DbUser'" -Silence) -eq 0) {
    Invoke-Sql "CREATE ROLE ""$DbUser"" LOGIN PASSWORD '$DbPassword'" -Silence | Out-Null
    Ok "role cree"
} else {
    Invoke-Sql "ALTER ROLE ""$DbUser"" LOGIN PASSWORD '$DbPassword'" -Silence | Out-Null
    Ok "role existant, mot de passe mis a jour"
}

# --- 4. Base -----------------------------------------------------------------
Etape "4/6  Base '$DbName'"
if ((Invoke-Sql "SELECT 1 FROM pg_database WHERE datname = '$DbName'" -Silence) -eq 0) {
    # CREATE DATABASE ne peut pas s'executer dans une transaction.
    Invoke-Sql "CREATE DATABASE ""$DbName"" OWNER ""$DbUser"" ENCODING 'UTF8'" -Silence | Out-Null
    Ok "base creee"
} else {
    Ok "base deja presente"
}

# --- 5. Schema ---------------------------------------------------------------
Etape "5/6  Schema de base"
if (-not (Test-Path $Schema)) { Err "Introuvable : $Schema"; exit 5 }
& $psql -U postgres -h localhost -p $Port -d $DbName -v ON_ERROR_STOP=1 -q -f $Schema 2>&1 |
    ForEach-Object { if ("$_" -match "ERROR|FATAL") { Err $_ } }
if ($LASTEXITCODE -ne 0) { Err "schema de base : echec"; exit 6 }
Ok "schema de base applique"

# --- 6. Migrations -----------------------------------------------------------
Etape "6/6  Migrations"
$migrations = @()
if (Test-Path $MigDir) {
    $migrations = Get-ChildItem -Path $MigDir -Filter "*.sql" | Sort-Object Name
}
foreach ($m in $migrations) {
    & $psql -U postgres -h localhost -p $Port -d $DbName -v ON_ERROR_STOP=1 -q -f $m.FullName 2>&1 |
        ForEach-Object { if ("$_" -match "ERROR|FATAL") { Err $_ } }
    if ($LASTEXITCODE -ne 0) { Err "migration en echec : $($m.Name)"; exit 7 }
    Ok $m.Name
}

# --- Verification ------------------------------------------------------------
Etape "Verification"
$nb = Invoke-Sql "SELECT count(*) FROM information_schema.tables WHERE table_schema='public' AND table_type='BASE TABLE'" -Database $DbName -Silence
Write-Host "  tables creees : $nb"

$manquantes = @()
foreach ($t in @("patient", "medecin", "dossier_patient", "evaluation_clinique", "compte")) {
    $trouvee = Invoke-Sql "SELECT count(*) FROM information_schema.tables WHERE table_schema='public' AND table_name='$t'" -Database $DbName -Silence
    if ("$trouvee".Trim() -eq "0") { $manquantes += $t }
}
if ($manquantes.Count -gt 0) { Err "tables manquantes : $($manquantes -join ', ')"; exit 8 }
Ok "tables essentielles presentes"

$url = "postgresql://$DbUser" + ":" + $DbPassword + "@localhost:$Port/$DbName"
Etape "Termine"
Say ""
Say "A reporter dans backend\.env :"
Write-Host "    DATABASE_URL=$url" -ForegroundColor Yellow
if ($genere) { Warn "Mot de passe genere : $DbPassword" }
Say ""
Say "  1. Recopier le DATABASE_URL dans backend\.env"
Say "  2. cd backend"
Say "  3. python -m app.bootstrap_admin"
Say "  4. python -m uvicorn app.main:app --reload --port 8000"
```

### Run it

```powershell
# If PostgreSQL is not installed yet:
.\pancreacare_local_postgres.ps1 -AutoInstall

# If it is already installed:
.\pancreacare_local_postgres.ps1
```

You will be prompted for the `postgres` administrator password. The script then
prints the `DATABASE_URL` to copy into `backend/.env`.

Optional arguments:

| Argument | Default | Purpose |
|---|---|---|
| `-DbName` | `pancreacare` | database name |
| `-DbUser` | `pancreacare` | application role |
| `-DbPassword` | *generated* | password for that role |
| `-Port` | `5432` | listening port |
| `-AdminPassword` | *prompted* | password of the `postgres` role |

### What the script does not do

It does **not** edit any project file. It reads the SQL and executes it. It
also deliberately does **not** copy your Supabase data — see
[section 7](#7-bringing-over-existing-supabase-data).

### Verification status of this script

Be aware of what has and has not actually been executed:

| Step | Status |
|---|---|
| PowerShell syntax | **Verified** — parsed with the PowerShell AST parser, no errors |
| UTF-8 BOM handling | **Verified** — BOM present, accents render correctly |
| "PostgreSQL absent" branch | **Verified** — exits with code 2 and prints instructions |
| Steps 2–6 (role, database, schema, migrations) | **Not executed** — no PostgreSQL instance was available in the authoring environment |

The unexecuted steps are ordinary `CREATE ROLE` / `CREATE DATABASE` / `psql -f`
calls, and the SQL they load has been validated as described in section 1. Run
it and report anything unexpected.

## 3. Method B — by hand, in SQL

If you prefer to do it interactively.

### 3.1 Create the role

`CREATE ROLE` cannot run inside a transaction, so it needs its own statement:

```sql
CREATE ROLE pancreacare LOGIN PASSWORD 'MotDePasse_Simple2026';
```

### 3.2 Create the database

```sql
CREATE DATABASE pancreacare OWNER pancreacare ENCODING 'UTF8';
```

> You must **disconnect and reconnect** to the new database before running the
> schema, or simply create it with a right-click → *New Database* in pgAdmin.

### 3.3 Load the schema and migrations

In pgAdmin, open the **Query Tool** against `pancreacare`, then either paste
each file in turn, or use psql from a terminal:

```powershell
cd "C:\Users\INFO\Desktop\CHU stage\Pancrea-care\backend"

psql -U postgres -d pancreacare -v ON_ERROR_STOP=1 -f database\pancra_db_schema_supabase.sql

Get-ChildItem -Path database\migrations -Filter *.sql | Sort-Object Name | ForEach-Object {
    Write-Host "Applying $($_.Name)"
    psql -U postgres -d pancreacare -v ON_ERROR_STOP=1 -f $_.FullName
}
```

`-v ON_ERROR_STOP=1` is important: without it `psql` reports an error but keeps
going, so a migration that failed halfway leaves the schema inconsistent and the
root cause is much harder to find later.

## 4. Method C — already have a database

To rebuild a schema from scratch into a database you already created:

```powershell
cd "C:\Users\INFO\Desktop\CHU stage\Pancrea-care\backend"

psql -U postgres -d ma_base -v ON_ERROR_STOP=1 -f database\pancra_db_schema_supabase.sql

Get-ChildItem -Path database\migrations -Filter *.sql | Sort-Object Name | ForEach-Object {
    psql -U postgres -d ma_base -v ON_ERROR_STOP=1 -f $_.FullName
}
```

If the base schema fails because the objects already exist, start from a clean
database — the schema is not designed to be applied over a partial one.

## 5. Verification

Run these against the local database. All of them should return sensible values.

```sql
-- How many tables?
SELECT count(*)
FROM information_schema.tables
WHERE table_schema = 'public' AND table_type = 'BASE TABLE';
-- expected: roughly 60

-- Are the essential tables present?
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'
  AND table_name IN ('patient', 'medecin', 'dossier_patient',
                     'evaluation_clinique', 'compte');
-- expected: 5 rows

-- Do the authentication tables exist?
\d public.compte
\d public.demande_reinitialisation

-- Did the identity columns land on `compte`?
SELECT column_name, data_type
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'compte'
ORDER BY ordinal_position;
-- expected to include nom, prenom, telephone, hopital

-- Are the medical enums present?
SELECT typname FROM pg_type t
JOIN pg_namespace n ON n.oid = t.typnamespace
WHERE n.nspname = 'public' AND t.typtype = 'e'
ORDER BY typname;

-- How many foreign keys does `dossier_patient` carry?
SELECT conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid = 'public.dossier_patient'::regclass AND contype = 'f';
```

## 6. Pointing the application at it

One line in `backend/.env`:

```dotenv
DATABASE_URL=postgresql://pancreacare:<mot_de_passe>@localhost:5432/pancreacare
```

This is configuration, not code, and `.env` is git-ignored. No source file
changes.

Then:

```powershell
cd backend
python -m app.bootstrap_admin
python -m uvicorn app.main:app --reload --port 8000
```

`bootstrap_admin` creates the first super admin **and** attaches a clinical
profile to it, so the account can use both `/admin` and `/dashboard`.

> **URL encoding.** If your password contains `@ : / ? # [ ] %`, percent-encode
> it in the URL (`@` becomes `%40`) or the connection string will be truncated
> or rejected. Method A avoids this by validating the password and refusing
> those characters.

### Going back to Supabase

Simply restore the previous `DATABASE_URL` and restart the backend. Nothing was
modified on the Supabase side.

## 7. Bringing over existing Supabase data

**The local database starts empty.** The migrations create the schema and the
administrative accounts; they do not copy your patients, dossiers, or
physician accounts from Supabase. This is intentional in Method A — a
`pg_dump` / `restore` pointed at the wrong database is a destructive mistake
worth confirming first.

To migrate the data, you need the PostgreSQL **client tools** (`pg_dump`), which
come with the PostgreSQL installation even though they are not currently on the
`PATH` in this environment:

```powershell
# 1. Export from Supabase (password is the one from your Supabase project)
$env:PGPASSWORD = "<mot_de_passe_supabase>"
pg_dump -h aws-0-eu-central-1.pooler.supabase.com -p 6543 -U postgres -d postgres `
    -Fc -f C:\temp\pancreacare.dump

# 2. Import into the local database
$env:PGPASSWORD = "<mot_de_passe_local>"
pg_restore -h localhost -p 5432 -U pancreacare -d pancreacare `
    --clean --if-exists C:\temp\pancreacare.dump
```

Caveats:

- The Supabase connection pooler on port **6543** is the transaction pooler. It
  is fine for `pg_dump`.
- `--clean --if-exists` drops existing objects first. **Remove it** if you want
  to merge into a non-empty database.
- Re-run `bootstrap_admin` afterwards if the imported `compte` rows conflict
  with an administrator you already created locally.

## 8. Troubleshooting

### `psql` is not recognised

PostgreSQL is not installed, or its `bin` directory is not on the `PATH`. Method
A searches `C:\Program Files\PostgreSQL\*\bin\psql.exe` directly, so it works
either way. To install:

```powershell
winget install --id PostgreSQL.PostgreSQL
```

The Windows installer asks you to set a password for the `postgres`
superuser. **Write it down** — provisioning scripts need it. The application
itself never uses that account.

### Connection refused on `localhost:5432`

- Wrong password for the `postgres` role.
- The server is listening on a different port. Check:

  ```powershell
  Get-Service postgresql*
  Get-Content "C:\Program Files\PostgreSQL\*\data\postgresql.conf" |
      Select-String "^#?port"
  ```

- `pg_hba.conf` is refusing local TCP connections. Look for a `host all all
  127.0.0.1/32 scram-sha-256` line.

### `invalid byte sequence for encoding "UTF8"`

Set the client encoding:

```powershell
$env:PGCLIENTENCODING = "UTF8"
```

The SQL files themselves are valid UTF-8; only the client needs to be told.

### `The terminator " is missing in the string` (PowerShell)

Your `.ps1` was saved as UTF-8 **without** BOM and PowerShell 5.1 misread a
multi-byte character. Re-save as **UTF-8 with BOM**, or strip all non-ASCII
characters.

### `relation "compte" does not exist`

The auth migration did not run, or it failed. Re-run the sequence:

```powershell
Get-ChildItem -Path database\migrations -Filter *.sql | Sort-Object Name |
    ForEach-Object { psql -U postgres -d pancreacare -v ON_ERROR_STOP=1 -f $_.FullName }
```

If you *did* run it, `ON_ERROR_STOP` was not honoured and an earlier statement
failed first — read the output for the **first** error, not the last one.

To apply a single migration with its output visible:

```powershell
psql -U postgres -d pancreacare -v ON_ERROR_STOP=1 `
    -f database\migrations\2026_10_05_auth_compte_admin.sql
```

A `CREATE TABLE` conflict means the object already exists, which is only
expected if you previously ran an incomplete sequence. The repair migrations
(`_identite`, `_super_admin_profil_medecin`) are idempotent and can always be
re-run.
